## What it is

SmolVM is an open-source (Apache 2.0) microVM runtime from Celesto AI for securely executing untrusted code generated by AI agents. It uses Firecracker (Linux/KVM) or QEMU (macOS) to provide hardware-level virtualization — stronger isolation than containers since guest VMs don't share the host kernel.

## Why it's interesting

It's an agent-first abstraction over microVMs with a clean Python SDK. Boot-to-SSH-ready in ~2.1s, command execution in ~43ms, full lifecycle in ~3.5s. Handles the painful parts (TAP networking, NAT, port forwarding, SSH tunneling, rootfs management) behind a simple API. Each VM gets an isolated disk clone by default (sandbox-by-default). Compare with [[isolating the entire agent in a sandbox is more secure than isolating just the tool|Browser Use's Unikraft approach]] (sub-second boot, similar philosophy) and [[OpenSandbox|Alibaba's OpenSandbox]] (Docker/K8s abstraction layer).

## How it works

- **Backend**: Firecracker on Linux (KVM), QEMU on macOS — auto-detected
- **SDK**: `pip install smolvm` — Python context manager API (`with SmolVM() as vm:`)
- **Isolation**: Per-VM writable rootfs clone (`disk_mode="isolated"` default), KVM hardware virtualization
- **Networking**: Built-in NAT, port forwarding via nftables (fallback to SSH tunnel), env var injection
- **Custom images**: Build specialized Debian-based rootfs images with your own tools
- **CLI**: `smolvm` command for env vars, diagnostics (`smolvm doctor`), benchmarking

## Notes

- SSH trust model uses `AutoAddPolicy` (no host key verification) — designed for local/trusted networks only, not public exposure.
- Performance: ~572ms create+start, ~2.1s SSH ready, ~43ms command exec, ~751ms stop+delete (AMD Ryzen 7, Firecracker).
- Could be relevant if we ever need agent sandboxing beyond Docker. Firecracker requires KVM, so won't work in nested virtualization (most cloud VMs) without bare metal or KVM-enabled instances.
